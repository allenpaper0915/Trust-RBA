# 移工聘僱關係與仲介供應鏈風險雷達

把事件、法定義務與證據之間的落差，整理成政府承辦人可以處置的風險預警。

2026 可信 AI 黑客松作品。這是一個可互動的原型，不是已上線系統。

---

## 這是什麼

現行制度已經要求聘僱、轉換、投保、發薪、居留、失聯與訪查留下資料。問題不是沒有資料，而是資料分散在不同機關、更新時間不同，而且多半要有人申報之後狀態才會改變。現場已經變了，正式紀錄還沒跟上。

這個系統做三件事：

1. 把跨機關事件、雇主申報與本人回報收進同一條時間軸。
2. 對照法規要求「什麼時候該出現什麼證據」，找出衝突、逾期與缺口。
3. 把結果整理成有依據、可追溯的案件，交給有權承辦人查證與處置。

核心是一條 **事件—義務—證據鏈**：

```
發生什麼事  →  依法應做什麼  →  何時該出現什麼證據  →  實際收到什麼  →  落差
```

## 這不是什麼

- 不是移工位置追蹤或即時監控。
- 不是自動裁罰，也不做違法認定。燈號代表查證優先序。
- 不是 RBA 官方認證，不宣稱保證合規。
- 不是政府、銀行與電信原始個資的集中資料庫。

---

## 四種角色

同一份資料，不同角色看到不同內容。角色切換會連帶換掉整個導覽。

| 角色 | 進入點 | 能做什麼 | 不能做什麼 |
|---|---|---|---|
| 政府承辦 | `/dashboard` | 狀態總覽、事件與衝突、仲介監理、訪查抽樣、稽核紀錄 | — |
| 移工本人 | `/worker` | 多語申報、上傳文件、查詢案件進度 | 看不到其他人的案件 |
| 仲介機構 | `/agency` | 提交本機構承辦的事件與補件 | 不能變更政府認定狀態 |
| 聘僱企業 | `/enterprise` | 取得辦理聘僱所需的可驗證聲明、舉證覆蓋、RBA 憑證 | 不調閱移工原始文件與完整申訴紀錄 |

移工端是唯一由移工本人操作的介面，支援四種語言，並在文件送出前於瀏覽器內完成去識別化。

---

## 五色燈

燈號評估的是「這個時間點的聘僱關係需要多少查證」，不是移工的信用分數，也不是違法判定。

| 燈號 | 意義 |
|---|---|
| 紅 | 多個可信來源直接衝突，需要人工介入 |
| 黃 | 逾期、缺漏或需要補證 |
| 藍 | 合法程序進行中，仍在期限內 |
| 灰 | 依法應有的資料目前不可得 |
| 綠 | 目前可取得的證據未發現異常 |

**灰燈不是綠燈。** 沒有資料不等於沒有問題，所以長期靜默的案件仍會進入抽樣，綠燈也保留隨機抽樣作為漏報率基線。

## 系統架構

```
前端　瀏覽器
  移工端（多語申報、送出前去識別化） ｜ 政府承辦端 ｜ 仲介端 ｜ 企業端
        ↕  HTTPS / JSON
後端　平台服務
  事件接收與正規化 ｜ 規則引擎（deterministic）｜ AI 理解服務
  證明與稽核 ｜ 案件與證據資料庫
        ↕  受控介接，每次調閱寫入稽核紀錄
外部來源　資料留在原機關
  T-Road（勞動部、移民署、勞保局）｜ MyData（本人授權）｜ 銀行、電信（最小訊號）
```

三個設計決定：

- **去識別化留在前端。** 未遮蔽的原始檔不離開移工的裝置。
- **判斷由規則產生，不由模型產生。** 燈號、分數與優先序全部來自固定的義務表、期限表與權重表，同一份輸入永遠得到同一個結果，可重算、可稽核、可申覆。
- **AI 只產生文字。** 多語翻譯、事件抽取、衝突摘要屬於解釋層，不參與任何計分。

## 目前實作範圍

這是黑客松原型，以下是誠實的邊界：

**已實作**

- 四種角色的完整介面與角色切換
- 事件—義務—證據鏈與五色燈判讀（`src/data/monitoring.ts`）
- deterministic 規則計分：固定權重表、匯率表、基準表（`src/lib/risk-engine.ts`、`src/lib/analysis.ts`）
- 瀏覽器內去識別化，固定樣式比對（`src/lib/deidentify.ts`）
- 證明層：SHA-256 雜湊鏈、Merkle root 與存在性證明、Web Crypto 簽章（`src/lib/proof.ts`）
- 跨案件仲介聚合（`src/lib/vendor-stats.ts`）
- 稽核紀錄與對外查驗頁

**尚未接入**

- AI 理解服務。目前程式碼沒有任何模型呼叫，相關畫面為流程示意。
- T-Road、MyData、銀行與電信介接。Demo 使用 `src/data/` 的種子資料。
- 後端與資料庫。目前狀態存在 React Context 與 `localStorage`，重新整理不會重設，`/reset` 才會。

**未驗證**

實際可用的跨機關 API、資料更新頻率、主責機關、個資法法源，以及本人回饋不受雇主或仲介控制的方法。

## 開發

```sh
bun install
bun run dev      # http://localhost:8080
bun run build
bun run lint
```

`/reset` 會把所有案件與事件回到初始狀態。

技術棧：TanStack Start · React 19 · Vite 8 · Tailwind CSS 4 · TypeScript，執行環境 Bun。

## 目錄

```
src/
  routes/          檔案式路由。__root.tsx 是唯一的 layout
    worker/        移工端（多語）
    cases/         案件佇列與單一案件
    vendors/       仲介跨案件監理
  components/
    platform-store.tsx   案件、事件與處置決定的單一來源
    app-shell.tsx        依角色切換導覽
  data/            案件模型與種子資料、燈號與監測案例
  lib/             規則、分析、去識別化、證明層
```

風險分數與金額一律由固定權重表與規則計算，不由模型產生。修改 `src/lib/risk-engine.ts` 的權重表會改變所有既有案件的分數，請一併更新對應的測試情境。
